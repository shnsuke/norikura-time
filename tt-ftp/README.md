# 峠TT FTPプランナー

峠のタイムトライアル(TT)結果から FTP を推定し、その FTP と体重から
期分けトレーニングメニュー（基礎期／ビルド期／特異期／ピーク期）の設定パワーを表示する、
スマホ向けの単一ページWebアプリです。ビルド不要（HTML/CSS/JavaScript のみ）。

## ファイル構成

```
tt-ftp/
  index.html         画面
  style.css          見た目
  app.js             画面の制御・localStorage への保存
  calc.js            計算ロジック（FTP推定・パワー推定・期と週の判定・%FTP→W変換）
  menus.json         期分けメニュー（%FTP で定義。自由に編集できます）
  zwo.js             メニュー → Zwift ワークアウト(.zwo) 変換
  intervals.js       メニュー → intervals.icu の予定ワークアウト（テキスト形式）変換と登録
  zwo/               全メニューの .zwo（tools/export-zwo.js で生成）
  tools/export-zwo.js
  test/              calc.js / zwo.js / intervals.js のユニットテスト
```

## 開き方

`menus.json` を `fetch` で読むため、`index.html` をファイルとして直接開く（`file://`）と
メニューが表示されません。次のどちらかで開いてください。

- **GitHub Pages**（スマホで使う場合）: `.github/workflows/pages.yml` がデフォルトブランチへの
  push 時に `tt-ftp/` を公開します。初回だけリポジトリの
  Settings → Pages → Build and deployment → Source を **GitHub Actions** にしてください。
  公開URLは `https://<ユーザー名>.github.io/norikura-time/` です。
- **ローカル**: `cd tt-ftp && python3 -m http.server 8000`（または `npx serve`）→ http://localhost:8000

データ（設定・TT履歴）はブラウザの localStorage に保存されます。端末・ブラウザごとに別々で、
ブラウザのサイトデータを消すと消えます。

## 使い方

1. **設定**タブで体重を入れる（必須）。FTP を手入力するとTT結果より優先されます（空欄に戻すと最新TTの値）。
   「詳細設定」で自転車＋装備重量・CdA・Crr・駆動損失・換算指数 k を変更できます。
2. **TT入力**タブで日付・峠名と結果を入れる。結果はその場で計算され、「保存」で履歴に残り、
   最新のTTが現在の FTP になります。
3. **メニュー**タブに今日の期・週・曜日のメニューが表示されます。期・週・曜日を切り替えて先の週も確認できます。
   各区間に W（5W単位で丸め）・W/kg・時間が出ます。
4. **履歴**タブでTT結果の一覧を確認・削除できます（削除は2回押し）。

## 乗鞍ヒルクライムの予想タイム（設定タブ）

体重と FTP が入っていると、設定タブに乗鞍エコーライン（乗鞍観光センター → 畳平口、20.5km・標高差1260m）の
予想タイム・平均パワー・区間ごとの速度とタイムを表示します。期分けの減量目標（60kg・58kg）にしたときの試算も並べます。

- 区間ごとの勾配は大会要項からの概算（観光センター→三本滝 8.7km/+410m、三本滝→位ヶ原山荘 8.3km/+480m、位ヶ原山荘→ゴール 3.5km/+370m）
- 各区間の空気密度は区間の平均標高から求め、モードBと同じ式を速度について解きます
- ペースは所要時間 t に見合うパワー `P = FTP × (60 / t)^k`（FTP推定の式の逆）とし、P と t が釣り合うまで反復します
- 例：FTP 323W・体重63kg → 約56分46秒（平均324W）

## 計算方法

### モードA：パワーメーターあり

```
FTP = P × (t / 60)^k        k の初期値 0.05
```

- t が 8〜60分の範囲外なら警告を表示します。
- 参考として「P × 0.95」（P を20分パワーとみなした値）も並べて表示します。

例：体重63kg、P=330W、t=40分
`(40/60)^0.05 = exp(0.05 × ln(2/3)) = exp(−0.020273) = 0.97993` → **FTP = 323.4W、5.13W/kg**
（アプリの表示・ユニットテストとも一致）

### モードB：タイムのみ

1. 入力した距離を道のり（斜辺）とみなし、水平距離 = √(距離² − 標高差²)、θ = atan(標高差 / 水平距離)、
   平均速度 v = 距離 / タイム
2. 空気密度 ρ = 1.225 × (1 − 2.25577×10⁻⁵ × 平均標高)^4.25588（平均標高が未入力なら 1.225）
3. 推定平均パワー
   `P = [ m総·9.81·v·(sinθ + Crr·cosθ) + 0.5·ρ·CdA·v³ ] / (1 − 駆動損失)`、m総 = 体重 + 自転車＋装備重量
4. この P と t をモードAの式に通して FTP を算出

勾配が一定と仮定した推定値です（画面にも表示）。実際の勾配変化やペースの上げ下げ、風は考慮しません。

## メニュー（menus.json）の編集

### 期と週の判定

- 各期の `start`〜`end` から今日の期を決めます。期の中は開始日から7日ずつ数えて週番号を出します。
- 通常の期は `blockWeeks`（=3）週で1ブロック。ブロックの最終週が回復週です。
- `"blocks": false` の期（ピーク期）はブロック制を使わず、`week1`〜`week4` をそのまま使います。

### その日のメニューの探し方

曜日ごとに、次の順で最初に見つかったテンプレートを使います。どこにも無い曜日は「休養」になります。

| 週 | 探す順 |
|---|---|
| 負荷週（ブロックBの第W週） | `block{B}` → `load{W}` → `load` |
| 回復週 | `block{B}Recovery` → `recovery` |
| ピーク期の第N週 | `week{N}` |

例：基礎期は `load` に1週間分を書き、木曜のSSTの伸ばし方だけ `block2`〜`block4` で上書きしています。
特異期の火曜は `load1`（30/15）と `load2`（4〜6分走）で週ごとに交互にしています。

### 1日のメニューの書き方

```json
"thu": {
  "title": "SST 3×15分",
  "segments": [
    { "label": "WU",  "pct": [55, 65], "min": 15 },
    { "label": "SST", "reps": 3, "work": { "pct": [88, 94], "min": 15 }, "rest": { "pct": 55, "min": 5 } },
    { "label": "30/15", "sets": 3, "reps": 13,
      "work": { "pct": 120, "sec": 30 }, "rest": { "pct": 50, "sec": 15 }, "setRest": { "pct": 50, "min": 5 } },
    { "label": "峠TT（全力）", "note": "パワー指定の無い区間", "min": 30 }
  ],
  "notes": ["その日のメモ（デッドリフトなど）"]
}
```

- `pct` は %FTP。単一値か `[下限, 上限]`。表示時に FTP × % を 5W 単位で丸めます。
- 時間は `min`（分）か `sec`（秒）。反復区間の合計時間は
  `work×reps + rest×(reps−1)` を1セットとし、`setRest` はセット間に入ります。
- `note` は区間の補足、`notes` はその日のメモです。期ごとの `focus` / `volume` / `weightTarget` / `notes`、
  全体の `commonNotes` は「○○期のポイント」に表示されます。

> 「Rattlesnake」は、ウォームアップ（65%・80%・120%の刺激）の後に
> 1セット =「1分 140%」→「(15秒 40% → 30秒 120/117/114/112/110%) 各3本」→「3分 50%」を
> 基礎期は2セット、ビルド期は3セット行う構成です。15秒つなぎが先に来る反復は `"restFirst": true` で表します。

編集後は `node --test` を実行すると、全期間の火・木・土にメニューがあるかと、
すべての区間が計算できるかを確認できます。

## Zwift に入れる（スマホだけで）

intervals.icu の Zwift 連携を使います。intervals.icu の予定表に入れたワークアウトのうち、
直近7日分が Zwift に自動で送られます（Zwift のホーム画面／カスタムワークアウトに表示）。

1. intervals.icu の Settings → Zwift の「Connect」で Zwift と連携する（初回だけ）
2. intervals.icu の Settings → Developer Settings で API キーを確認する
3. このアプリの「設定」→「Zwift に送る」に API キーを貼り、「今日から4週間を登録」か「レースまで全部登録」を押す

- 予定は日付ごとに `external_id`（`ttftp-YYYY-MM-DD`）付きで登録するので、登録し直すと同じ日の予定が上書きされます。
  `menus.json` を変えたり FTP を更新したりした後も、もう一度押せば反映されます。
- 強度は %FTP で入ります。Zwift と intervals.icu の FTP をこのアプリの FTP に合わせてください。
- claude.ai 上のページからは外部サービスに接続できないため、登録ボタンは **GitHub Pages 版**で使ってください。
  claude.ai 上のページでは、メニュー画面の「intervals.icu 用にコピー」で1日分のテキストをコピーし、
  intervals.icu でワークアウトを追加して説明欄に貼る方法が使えます。

## Zwift に入れる（PC / Mac にファイルを置く）

.zwo の強度は %FTP で書かれるため、**Zwift の FTP をこのアプリと同じ値に合わせて**ください
（Zwift のメニュー → 設定 → ユーザー情報 → FTP）。W は Zwift 側で FTP × % で計算されます。

### 全メニューをまとめて入れる（PC / Mac）

1. このリポジトリの `tt-ftp/zwo/` フォルダを入手する（GitHub の「Code → Download ZIP」など）
2. 中身の `1-base` 〜 `4-peak` フォルダを Zwift のワークアウトフォルダにコピーする
   - Windows: `ドキュメント\Zwift\Workouts\<数字のフォルダ>\`
   - Mac: `書類/Zwift/Workouts/<数字のフォルダ>/`
   - `<数字のフォルダ>` は Zwift のユーザーID。一度 Zwift にログインすると作られます
3. Zwift を起動 → ワークアウト → カスタムワークアウト に期ごとに表示されます

ファイル名は `<テンプレート>-<曜日>.zwo` です（例：`load-2tue.zwo` = 負荷週の火曜、
`block3-4thu.zwo` = ブロック3の負荷週の木曜、`recovery-6sat.zwo` = 回復週の土曜、`week4-4thu.zwo` = ピーク期4週目の木曜）。
どの週にどれを使うかは、アプリのメニュー画面の週の表示（ブロック番号・負荷週/回復週）を見てください。

### その日の分だけ入れる

メニュー画面の「Zwift用ファイル（.zwo）を保存」で、表示中の日のファイルを保存できます
（ファイル名は日付入り）。上と同じフォルダに置いてください。
claude.ai 上のページではブラウザの制限でファイルを保存できないため、GitHub Pages 版かローカルで開いてください。

### 変換のルール

- `pct` が範囲のときは中央値を目標にします（例：88〜94% → 91%）。ラベルが WU / Warm-Up の範囲指定はランプアップ、CD はランプダウン
- 反復は `IntervalsT`、パワー指定の無い区間（峠TT など）は自由走行（FreeRide）
- その日のメモ（デッドリフトなど）はワークアウトの説明文に入ります

`menus.json` を編集したら、次のコマンドで `zwo/` を作り直してコミットしてください（CI で一致を確認しています）。

```sh
cd tt-ftp
node tools/export-zwo.js
```
